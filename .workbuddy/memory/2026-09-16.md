# 2026-09-16

## 新增 18-pg-flex 模块（PostgreSQL 灵活处理）
- 在 `crates/18-pg-flex` 下新增 crate，package 名 `pg-flex`。
- 设计目标：本地 PostgreSQL 的「灵活便捷自定义处理」——任意查询直接得 JSON，无需为每个结果手写结构体；提供泛型 CRUD（insert/find_all/find_where/update_where/delete_where）。
- 核心文件：`src/db.rs`（连接池+配置，读 `DATABASE_URL` 缺省本地 study 库）、`src/flex.rs`（`PqValue` 灵活值枚举 + `PgRow`→`serde_json::Value` 按 `type_info().name()` 解码 + `bind_value` 参数绑定 + 泛型 CRUD）、`src/main.rs`（迁移+演示）、`migrations/01_init.sql`（users 表）。
- 运行：`cargo run -p pg-flex`，需本地 PostgreSQL（docker 起 postgres:16 + `CREATE DATABASE study`）。

### SQLx 0.9 踩坑（可复用）
- 动态拼接的 SQL 不能传给 `sqlx::query()`（要求 `&'static str`/`SqlSafeStr`），必须用 `sqlx::query(sqlx::AssertSqlSafe(sql))` 包裹，附注入审计说明。
- `Query` 结构体在 0.9 是 `Query<'q, DB, A>`，无 A 默认参数；Postgres 参数类型用 `<Postgres as sqlx::Database>::Arguments`，可用类型别名简化。
- 判断列是否为 NULL 需 `use sqlx::ValueRef;`（`is_null` 来自该 trait）。
- workspace 的 sqlx 依赖已加 `postgres` + `chrono` 特性（chrono 用于 TIMESTAMP/TIMESTAMPTZ 解码为字符串）。
